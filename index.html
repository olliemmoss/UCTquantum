Motivation

Recall the languages defined for the arithmetic hierarchy: $\Sigma_2^P$ is all languages that have a poly-time verifier $V$ such that $x \in L \iff \exists y_1 \forall y_2 V(x, y_1, y_2) = 1$. $\Pi_2^P$ is just co-$\Sigma_2^P$.

By adding more quantifiers, we can define $\Sigma_k^P$ and $\Pi_k^P$ for any $k \geq 1$. The union of all these classes is called the polynomial hierarchy ($\PH$).

A reasonable question to ask about these $\PH$ classes: do they have a TM representing them? For example, $\NP$ is represented by NTMs and $\BPP$ is represented by PTMs. Does there exist an analogue for these classes?

The answer is yes, and we represent it using Alternating Turing Machines (ATMs). Let's derive their definition from this want: Specifically, we'd like to write a statement like: $$\Sigma_2^\P = \{L: \exists A, \text{$A$ is a 2-$\Sigma$ATM that that solves $L$ in poly-time}\}$$ To start off, let's not worry about bounding the number of quantifiers, to just get a feel for what an ATM is. Such a machine would be a generalization of an NTM, where we can have both existential and universal states. In an existential state, the machine accepts if there exists a transition that leads to acceptance. In a universal state, the machine accepts if all transitions lead to acceptance.

Definition

An ATM is a 6-tuple $(Q, \Sigma, \Gamma, \delta, q_0, g)$ where:
  • $Q$ is a finite set of states
  • $\Sigma$ is the input alphabet not containing the blank symbol $\sqcup$
  • $\Gamma$ is the tape alphabet, where $\Sigma \subseteq \Gamma$ and $\sqcup \in \Gamma$
  • $\delta: Q \times \Gamma \to \mathcal{P}(Q \times \Gamma \times \{L, R\})$ is the transition function
  • $q_0 \in Q$ is the start state
  • $g: Q \to \{\text{acc}, \text{rej}, \exists, \forall\}$ gives us the type of each state
We define configurations as expected, just keeping track of the state, tape contents, and head position.
  • If $g(q) = \text{acc}$, the configuration is accepting
  • If $g(q) = \text{rej}$, the configuration is rejecting
  • If $g(q) = \exists$, the configuration is accepting iff we can reach an accepting configuration after one step of the transition function (picking any of its outputs)
  • If $g(q) = \forall$, the configuration is accepting iff all configurations reachable in one step are accepting
See that we can visualize this as a tree1, where each node is a configuration, and the children of a node are all the configurations reachable in one step. We say that an ATM accepts an input if the root of this tree (the ATM where the tape is just $x$, the state is $q_0$, and the tape head is at the beginning) is an accepting configuration.

To model this as a process, as we normally think about TMs, we can think of the ATM as "switching" between existential and universal states. In an existential state, the machine can "guess" a transition to take, and in a universal state, the machine must "try" all transitions. This is a generalization of NTMs, where we only have existential states.

Since our goal is to model existence and universality, and we've been talking about $\NP$ as $\exists \P$, we should be able to simulate NTMs with ATMs. This is easy to do - just take an NTM and define it to be an ATM where the accepting/rejecting states are acc/rej, and all other states are $\vee$. Completely eliminate intermediate "coin-flip" states - just have the ATM transition to the two states that coin-flip states would have transitioned to. This is a valid ATM, and it accepts the same language as the NTM.

A cool result of this is that we can immediately define "co-NTM"s, which solve $\coNP$ problems, as ATMs where every intermediate state is $\wedge$.

Complexity

Before we talk about complexity classes derived from ATMs, let's talk about the complexity of ATMs themselves. Note this is weird - we've defined ATMs more as trees than as machines, so we should respect this in our complexity definitions. We define the complexity with the ATM with respect to the set of configurations that are necessary to inspect to determine if the ATM accepts or rejects.

The time complexity (given a certain input) is the maximum, over all configurations necessary to inspect, of the number of steps to get from the starting configuration to that configuration. Observe that this is upper bounded by, but not always equal to, the depth of the tree. In particular, $\vee$ states with an acc child or $\wedge$ states with a rej child can consider themselves foregone conclusions - even if the tree extends further down, we don't need to inspect those configurations to determine the result of the ATM. Finally, the time complexity of the machine is $$T_A : \mathbb{N} \to \mathbb{N}= \max_{|x|=n} \{\text{time complexity of $A(x)$}\}$$ Similarly, we define space complexity as the maximum, over all all configurations necessary to inspect, of the size of the range of tape cells modified. As before, this is the maximum over all inputs of length $n$. With this framework, it's reasonable to talk about "poly-time" and "poly-space" ATMs.

Bounded ATMs

We can also define bounded ATMs, which are ATMs that can only alternate a certain number of times. Formally, we say that an ATM is $k$-bounded (or it's a $k$-ATM) if its states can be partitioned into $k$ sets which alternate between being only $\wedge$ states and only $\vee$ states, and if $i < j$, there are no transitions from a state in set j to a state in set i. This enforces that in any computation path, the machine can only alter between existential and universal states at most $k$ times.

Further, we say that an ATM is $\Sigma_k$ if its start state is existential, and $\Pi_k$ if its start state is universal. NTMs are just $\Sigma_1$ ATMs. Now we have what we wanted before - a definition of $\Sigma_k^P$ and $\Pi_k^P$ in terms of solely ATMs. $\Sigma_k^\P$ is all languages that can be solved by a poly-time $\Sigma_k$ ATM. $\PH$ is the union of all these classes, and we can define it as the class of languages that can be solved by ATMs with a bounded number of alternations.

Complexity Classes

Now we can automatically fire off the definitions of a bunch of complexity classes.
  • $\ATIME(t(n))$ is all languages that can be solved by an ATM in $O(t(n))$ time.
  • $\ASPACE(s(n))$ is all languages that can be solved by an ATM in $O(s(n))$ space.
  • $\text{A}_k\TIME(t(n))$ is all languages that can be solved by a $k$-ATM in $O(t(n))$ time.
  • $\text{A}_k\SPACE(s(n))$ is all languages that can be solved by a $k$-ATM in $O(s(n))$ space.
  • $\Sigma_k\TIME(t(n))$ is all languages that can be solved by a $\Sigma_k$ ATM in $O(t(n))$ time.
  • $\Pi_k\TIME(t(n))$ is all languages that can be solved by a $\Pi_k$ ATM in $O(t(n))$ time.
  • $\Sigma_k\SPACE(s(n))$ is all languages that can be solved by a $\Sigma_k$ ATM in $O(s(n))$ space.
  • $\Pi_k\SPACE(s(n))$ is all languages that can be solved by a $\Pi_k$ ATM in $O(s(n))$ space.
  • $\AP = \bigcup_{k > 0} \ATIME(n^k)$
  • $\APSPACE = \bigcup_{k > 0} \ASPACE(n^k)$
...and we can just keep going. However, I claim that we may want to stop here, because we're not actually naming new complexity classes. In particular, for $f(n) \geq \log_2 n$:
  • $\ASPACE(f(n)) = \TIME(2^{O(f(n))})$
  • $\ATIME(f(n)) \subseteq \SPACE(f(n))$
  • $\NSPACE(f(n)) \subseteq \ATIME(f(n)^2)$
